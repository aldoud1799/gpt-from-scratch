# GPT From Scratch — PyTorch

A small, decoder-only GPT language model built from scratch in PyTorch. This project explores transformer architecture, efficient attention, memory-conscious training, and autoregressive text generation.

## Project Overview

The model is trained on TinyStories, a dataset of short stories, using the GPT-2 tokenizer. The implementation is designed as a hands-on learning project for understanding how GPT-style language models work internally.

## Model Architecture

The model uses approximately 20 million parameters and includes:

- **Decoder-only Transformer:** 7 transformer blocks
- **Grouped-Query Attention (GQA):** 8 query heads and 4 key/value heads
- **Rotary Position Embeddings (RoPE):** applied to queries and keys
- **SwiGLU:** gated feed-forward network
- **RMSNorm:** pre-normalization in transformer blocks and final normalization
- **Weight tying:** shared weights between token embeddings and the language-model output head
- **Causal attention mask:** prevents tokens from attending to future positions

### Model Configuration

| Setting | Value |
|---|---:|
| Embedding dimension | 256 |
| Transformer blocks | 7 |
| Query attention heads | 8 |
| Key/value attention heads | 4 |
| Head dimension | 32 |
| Context length | 512 tokens |
| Training batch size | 8 |
| Tokenizer | GPT-2 |

## Training Techniques

The training implementation includes:

- Mixed-precision training using PyTorch autocast and GradScaler
- Gradient accumulation over 32 microbatches
- Gradient checkpointing to reduce activation memory usage
- Custom parameter initialization
- Residual-output weight scaling
- Validation-loss monitoring and best-checkpoint saving

## Data Pipeline

The notebook uses the GPT-2 tokenizer from the Hugging Face `tokenizers` library.

The data pipeline:
1. Reads the TinyStories training text.
2. Tokenizes text in chunks.
3. Saves tokenized chunks and combines them into a token tensor.
4. Splits the token sequence into training (70%), validation (20%), and test (10%) sets.
5. Samples fixed-length input and next-token target sequences for training.

## Evaluation and Generation

The notebook includes:
- Validation-loss estimation over multiple batches
- Saving the model checkpoint when validation loss improves
- Test-loss evaluation after training
- Greedy autoregressive generation using the highest-probability next token

## How to Run

1. Open the notebook in Google Colab.
2. Enable a GPU runtime.
3. Mount Google Drive when prompted.
4. Place the TinyStories training text at the path expected by the notebook, or update the dataset path in the configuration.
5. Run the notebook cells in order.

The notebook currently uses Google Drive paths for the dataset, tokenized data, and model checkpoint. These files are not included in this repository.

## Current Scope and Limitations

This is an educational-scale GPT implementation, not a production-ready general-purpose language model.

The current notebook does not implement KV caching, gradient clipping, or learning-rate scheduling. Generation recomputes the model over the growing context at each step.

## Learning Goals

This project demonstrates practical work with:
- Transformer architecture and attention mechanisms
- Language-model training and next-token prediction
- Efficient training techniques in PyTorch
- Dataset tokenization and splitting
- Validation, checkpointing, and text generation

### Observations

The model generates simple English sentences and recognizable story patterns. However, some outputs contain repetition, incomplete sentences, grammatical errors, and inconsistent narrative development.

These results illustrate the capabilities and limitations of a small GPT-style language model trained on TinyStories.
